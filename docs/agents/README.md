# Multi-Agent Coordination Protocol — voice-acp

> איך סוכנים מקבילים על אותו פרויקט מסונכרנים בלי לדרוס אחד את השני.

## עיקרון מרכזי

**כל סוכן כותב רק לקובץ אחד — שלו.** כל הסוכנים יכולים לקרוא את כל הקבצים.
ככה אין race conditions של כתיבה בו-זמנית לאותו קובץ.

## מבנה התיקייה

```
docs/agents/
├── README.md       — הקובץ הזה. מסביר את הפרוטוקול.
├── planner.md      — סוכן התכנון. רק הוא כותב לכאן.
├── executor.md     — סוכן הביצוע. רק הוא כותב לכאן.
└── (executor-2.md, executor-3.md... אם יש כמה מבצעים)
```

## פורמט קובץ סוכן

לוג כרונולוגי, **חדש למעלה**:

```markdown
# {agent_name}

## מצב נוכחי
- **סטטוס:** פעיל / ממתין לתשובה / בהפסקה / סיים
- **Worktree:** `/path/to/worktree`
- **עובד על:** תיאור קצר של המשימה הנוכחית

## לוג

### [YYYY-MM-DD HH:MM] {כותרת}
תוכן.
```

## תקשורת בין סוכנים

לסוכן אחר אי אפשר לכתוב — אבל ניתן **להגיש שאלה/תשובה דרך הקובץ שלך**:

- **שאלה** — מבצע כותב לקובץ שלו:
  > ### [10:30] ❓ שאלה למתכנן: האם להשתמש ב-A או ב-B?
  >
  > נתקלתי ב-X. שתי אפשרויות: A (יתרון/חיסרון), B (יתרון/חיסרון).
  > ממתין לתשובה.

- **תשובה** — מתכנן כותב לקובץ שלו:
  > ### [10:35] ✅ תשובה למבצע (לשאלה מ-10:30): השתמש ב-B
  >
  > הסיבה: ...

המבצע עוקב אחרי `planner.md`, רואה את התשובה, וממשיך.

## כללי עבודה

1. **התחלת סשן** — קרא את כל הקבצים בתיקייה. עדכן את **המצב הנוכחי** שלך
   + הוסף ערך לוג "התחלתי סשן".

2. **בזמן עבודה** — כל ~5-10 דקות, עדכן את "עובד על". אם הסטטוס משתנה
   (התחלת משימה חדשה, סיימת, ממתין) — עדכן מיד.

3. **שאלות** — אם נתקעת במשהו עקרוני (החלטת ארכיטקטורה, סקופ, סדר עדיפויות):
   - כתוב את השאלה בלוג שלך עם הסימן ❓
   - שנה סטטוס ל"ממתין לתשובה"
   - **המשך עם משימות אחרות שאינן תלויות בתשובה** (לא להישאר בטל)
   - אם אין יותר משימות עצמאיות — סטטוס "בהפסקה" + ערך לוג "אין משימות זמינות,
     ממתין"

4. **סיום סשן** — עדכן סטטוס ל"סיים" + ערך לוג "סיימתי. הצעדים הבאים: X".

## טיפול ב-race condition (אם קורה)

אם בכל זאת שני תהליכים מנסים לכתוב לאותו קובץ (למשל בעקבות באג בפרוטוקול):

- **append-only files** (כמו לוג): כתיבות קצרות באורך פחות מ-PIPE_BUF (4KB ב-Linux)
  הן אטומיות ברמת ה-OS. כתיבות ארוכות יותר עלולות להתערבב.
- **פתרון פשוט:** לעטוף בנעילת קובץ (`flock` במערכת קבצים מקומית) או לכתוב לקובץ
  זמני ולעשות `rename` אטומי.
- **לעת עתה:** הסתמכות על כך שכל סוכן יכתוב לקובץ משלו = אין conflict.

## איך המשתמש מקבל התראה

כרגע — `tail -f docs/agents/*.md` בטרמינל. בעתיד נשקול notifications אקטיביות.
