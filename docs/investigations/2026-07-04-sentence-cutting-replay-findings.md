## 2. הממצא המרכזי — **חיתוך-אמצע-מילה אמיתי קיים בשכבת-הטקסט, ואינו נגרם מ-RLM**

| `הודעת` | `…על ה` | `ודעת הקומיט` |

  ‏ה-replay ‏על **‏זרימה הדרגתית אמיתית** ‏מוכיח שהחיתוך ב**‏טקסט**, ‏בסגמנטציה.

## 3. השורש — מוכח בבידוד (`isolate2.ts`)

ה-buffer ה**‏שלם** ‏לא נחתך. ‏החיתוך נובע מה**‏עיבוד ההדרגתי** ‏במסלול **‏רב-הפסקאות**:

```
chunk#1 = "…להיחשב.\n\n### מ"   ← גבול-chunk נופל באמצע מילה, וה-buffer כבר רב-פסקאתי (יש \n\n)
→ splitIntoSentences במסלול isMulti:
   seg "…להיחשב."   (פסקה 1 — מסתיימת)
   seg "### מ"       ← השארית החצי-מילה של הפסקה האחרונה נפלטת! (commit-everything)
chunk#2 = "ה נשאר פתוח…" → seg "ה נשאר פתוח (לא חוסם)"
⇒ "מה" נחצה בין שני סגמנטים.
```
control ‏חד-פסקאתי (‏ללא `\n\n`): ‏**‏אין חיתוך** — ‏השארית מוחזקת נכון.

**‏נקודת-הקוד:** `packages/core/src/voice/sentence-boundary.ts:65`
```ts
if (isLastPara && isLastSeg && !isMulti) {   // ← ה-!isMulti הוא הבאג
  if (TERMINATOR_RE.test(seg)) completed.push(seg)
  else remaining = seg                        // מחזיק שארית — רק בפסקה בודדת
} else {
  completed.push(seg)                          // רב-פסקאות → מחייב הכל, כולל שארית חצי-מילה של הפסקה האחרונה
}
```
‏הפסקה ה**‏אחרונה** ‏של buffer ‏רב-פסקאתי ‏עדיין בזרימה (‏אין `\n\n` ‏אחריה) — ‏ולכן צריך להחזיק את זנבה כ-`remaining`,
‏בדיוק כמו במקרה חד-הפסקה. ‏הפסקאות `1..n-1` (‏שכן ‏מסתיימות ב-`\n\n`) ‏נכון לחייב במלואן.
